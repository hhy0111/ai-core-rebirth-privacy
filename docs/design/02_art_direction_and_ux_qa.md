# 아트 디렉션 및 UX QA 초안

문서 목적: Google Play Android 전용 2D 방치형 하이브리드 캐주얼 MVP의 비주얼 방향, UX 검수 기준, QA 1~3차 사이클 기준을 정의한다.

범위 원칙:
- 개인 개발자가 제작 가능한 2D 리소스 기준으로 제한한다.
- 대형 시네마틱, 복잡한 본 애니메이션, 3D 연출, 서버 기반 라이브 아트 파이프라인은 제외한다.
- 행성 변화, AI 캐릭터 UI, 자원/복원/워프/진화/경고 이펙트가 스크린샷만으로 읽히는 것을 우선한다.

## 10. 아트 디렉션 작성

* 담당 에이전트: Visual Designer, Visual Design Lead
* 목표: 2D 탑다운, 카툰, 네온 SF 스타일을 기준으로 중앙 행성 변화와 AI 캐릭터 UI가 즉시 이해되는 MVP 아트 기준을 확정한다.
* 구현/기획 범위:
  - 화면 구조: 중앙 행성 60%, 상단 자원 UI 15%, 하단 기능 버튼 20%, 우측 또는 하단 보조 영역에 AI 캐릭터 메시지 5%를 기본 비율로 잡는다.
  - 행성 상태: 붕괴 상태는 균열, 잿빛 지형, 꺼진 코어를 사용한다. 활성화는 코어 발광, 에너지 라인, 작은 초록/청록 포인트를 추가한다. 성장은 식생, 구조물, 궤도 드론, 밝은 대기층을 추가한다. 완성은 안정된 오라, 완전한 지형 색, 주변 위성/링 이펙트로 표현한다.
  - 행성 5개: 기본 구형 실루엣은 공통으로 유지하고, 색상 팔레트와 표면 패턴만 다르게 제작한다. 각 행성은 4단계 상태 스프라이트 또는 레이어 조합으로 구현한다.
  - AI 캐릭터 UI: 원형 홀로그램 코어 얼굴을 기본형으로 한다. 생명형은 부드러운 청록/초록, 산업형은 흰색/노랑/금속 회색, 전투형은 빨강/마젠타/강한 대비를 사용한다. 표정은 기본, 기쁨, 경고, 분석, 오류 5종만 제작한다.
  - UI 스타일: 카툰식 굵은 외곽선, 네온 하이라이트, 어두운 우주 배경, 선명한 자원 아이콘을 사용한다. 버튼은 하단 5개 고정 탭으로 배치하고, 아이콘과 짧은 라벨을 함께 사용한다.
  - 에너지 생산 이펙트: 행성 표면에서 작은 빛 입자가 생성되어 상단 자원 UI로 이동하는 0.4~0.7초 파티클로 처리한다.
  - 행성 복원 이펙트: 단계 전환 시 균열이 빛으로 메워지고 표면 색이 밝아지는 1초 이하의 레이어 페이드와 링 파동을 사용한다.
  - 업그레이드 완료 이펙트: 버튼 근처의 짧은 플래시, 행성의 작은 펄스, 자원 수치 상승 애니메이션으로 제한한다.
  - 행성 이동 워프 이펙트: 전체 화면을 덮는 시네마틱 대신 중앙 행성이 작아지고 별점이 방사형으로 흐르는 1.2초 이하 전환으로 구현한다.
  - 진화 선택 연출: 생명형/산업형/전투형 3개 카드를 같은 크기로 제시하고, 선택 시 해당 색상의 회로가 AI 코어와 행성을 연결하는 짧은 연출을 사용한다.
  - 랜덤 이벤트 경고 연출: 화면 흔들림은 약하게 제한하고, 상단 경고 배너, AI 경고 표정, 행성 가장자리 붉은 링으로 위험을 표현한다.
* 산출물:
  - 행성 5개 x 상태 4단계 제작 기준.
  - AI 성향 3종 x 표정 5종 제작 기준.
  - 상단 자원 UI, 하단 탭 UI, 업그레이드/이동/AI/이벤트/상점 패널 방향.
  - 에너지, 복원, 업그레이드, 워프, 진화, 경고 이펙트의 최소 구현 기준.
  - Google Play 스크린샷에 사용할 대표 장면 기준: 붕괴 행성, 성장 행성, 진화 선택, AI 이벤트, 은하 이동.
* 발견된 문제:
  - 행성 5개를 모두 완전 신규 아트로 제작하면 개인 개발자 기준 제작량이 과도하다.
  - 네온 SF UI는 작은 모바일 화면에서 과하면 자원 수치와 버튼 가독성을 해칠 수 있다.
  - AI 메시지가 길어지면 방치형 게임의 빠른 세션 흐름을 방해할 수 있다.
* 수정 지시:
  - 행성은 공통 베이스, 행성별 표면 패턴, 상태별 오버레이로 분리해 재사용한다.
  - 네온 효과는 버튼 테두리와 중요 상태에만 사용하고, 본문 텍스트 배경은 고대비 단색 패널을 사용한다.
  - AI 메시지는 기본 1~2줄, 이벤트/진화 상황에서도 최대 3줄로 제한한다.
  - 완성 단계 연출은 반복 파티클 수를 제한하고 정적 광원 레이어를 활용한다.
* 성공 기준:
  - 첫 화면 5초 안에 중앙 행성, 자원, 업그레이드 버튼, AI 캐릭터의 역할이 구분된다.
  - 행성 4단계가 축소된 모바일 화면에서도 명확히 다르게 보인다.
  - AI 성향 3종이 색, 표정, 말투 UI로 구분된다.
  - 이펙트가 보상감은 주지만 자원 UI와 버튼 조작을 가리지 않는다.
* 검증 방법:
  - 720x1280, 1080x1920, 1440x3120 세로 화면 목업에서 가독성을 확인한다.
  - 흑백 또는 저채도 변환 상태에서도 주요 버튼과 행성 단계가 구분되는지 확인한다.
  - 1분 플레이 영상 기준으로 업그레이드, 자원 획득, 행성 변화, AI 반응이 최소 1회씩 보이는지 확인한다.
  - 3명 이상에게 10초 스크린샷 테스트를 진행해 "행성을 복원하는 게임"이라는 응답이 나오는지 확인한다.
* 승인 상태: Approved

## 13. 내부 검수

* 담당 에이전트: Visual Design Lead, QA Agent B, QA Lead
* 목표: MVP 기획/개발 산출물이 비주얼 방향과 1~3분 세션 UX 기준을 충족하는지 사전 검수한다.
* 구현/기획 범위:
  - 메인 화면 정보 구조 검수: 자원, 행성, AI, 하단 기능 버튼의 우선순위가 명확한지 확인한다.
  - 행성 상태 변화 검수: 붕괴, 활성화, 성장, 완성이 단순 색 변경에 그치지 않는지 확인한다.
  - AI 캐릭터성 검수: 생명형, 산업형, 전투형의 추천 문구와 표정이 실제 선택 상황에 연결되는지 확인한다.
  - 반복 세션 검수: 1~3분 안에 자원 생산, 업그레이드, 시각 피드백, 다음 목표가 모두 노출되는지 확인한다.
  - 수익 UX 검수: 광고/상점 버튼이 진행을 방해하지 않고 선택형 보상으로 보이는지 확인한다.
* 산출물:
  - 내부 검수 리포트: Pass, Minor, Major, Blocker 4등급으로 분류한다.
  - 화면별 수정 목록: 메인, 업그레이드, 이동, AI, 이벤트, 상점, 진화 선택.
  - 출시 차단 후보 목록: UI 이해 불가, 진행 목표 불명확, 광고 강요 인상, AI 캐릭터성 부족.
* 발견된 문제:
  - 초기 화면에 기능 버튼 5개가 동시에 노출되어 신규 유저가 첫 행동을 놓칠 가능성이 있다.
  - 행성 변화가 수치 성장과 연결되지 않으면 시각 변화가 장식으로 느껴질 수 있다.
  - 진화 선택 카드가 보너스 설명만 제공하면 플레이 방향 변화가 약하게 보인다.
* 수정 지시:
  - 첫 세션에서는 업그레이드 버튼과 AI 안내를 우선 강조하고, 이동/상점은 잠금 또는 낮은 강조 상태로 시작한다.
  - 행성 단계별로 생산량 배수, 해금 기능, 배경 효과를 UI에 함께 표시한다.
  - 진화 선택 카드는 즉시 효과, 누적 효과, 리스크를 같은 위치에 짧게 표시한다.
  - 광고 보상 버튼에는 "선택 보상" 성격이 보이도록 무료 진행 버튼과 같은 화면에 배치한다.
* 성공 기준:
  - 내부 검수에서 Blocker가 0개다.
  - Major 항목은 QA 1차 진입 전 수정 지시가 작성되어 있다.
  - 메인 화면만 보고도 유저의 다음 행동이 업그레이드 또는 터치 가속으로 유도된다.
  - AI가 단순 알림창이 아니라 선택 해석자 역할을 한다.
* 검증 방법:
  - 화면 플로우를 30초 단위로 재생하며 유저 행동 후보를 기록한다.
  - 메인 화면, 업그레이드 패널, 진화 선택, 이벤트 팝업을 실제 모바일 비율로 캡처해 UI 겹침을 확인한다.
  - AI 메시지 20개 샘플을 읽고 성향별 말투 차이와 길이 제한 준수 여부를 확인한다.
* 승인 상태: Approved

## 14. QA 1차

* 담당 에이전트: QA Agent B, QA Lead
* 목표: 첫 플레이 1~3분의 이해도, 조작감, 보상감, 시각 피드백을 검증한다.
* 구현/기획 범위:
  - QA 1차는 메인 루프의 UX 스모크 테스트로 제한한다.
  - 검수 대상은 첫 행성, 기본 자원 생산, 첫 업그레이드, 첫 행성 단계 변화, AI 기본 안내, 하단 버튼 가독성이다.
  - 결제와 광고는 실제 SDK 연동 전이라도 버튼 위치, 문구, 선택형 보상 흐름을 목업 상태로 검수한다.
* 산출물:
  - QA 1차 체크 항목: 첫 5초 안에 행성/자원/업그레이드 인지 가능, 15초 안에 첫 보상 수령 가능, 60초 안에 첫 업그레이드 가능, 180초 안에 행성 변화 또는 다음 목표 인지 가능.
  - QA 1차 체크 항목: 터치 가속 피드백이 즉시 보임, 자원 수치 증가가 읽힘, 버튼 텍스트가 잘리지 않음, AI 메시지가 조작을 가리지 않음, 경고/이벤트 팝업이 닫기 쉽다.
  - QA 1차 체크 항목: 720x1280 저해상도 기준 하단 탭 5개가 겹치지 않음, 상단 자원 UI 3종이 구분됨, 행성 중심 오브젝트가 화면에서 가장 크게 보임.
  - QA 1차 반려 조건: 첫 30초 동안 해야 할 행동을 알 수 없음.
  - QA 1차 반려 조건: 첫 업그레이드가 3분 안에 발생하지 않거나 보상감이 없다.
  - QA 1차 반려 조건: 행성 단계 변화가 시각적으로 확인되지 않는다.
  - QA 1차 반려 조건: AI 메시지, 이벤트 팝업, 광고 보상 버튼이 핵심 조작을 가린다.
  - QA 1차 반려 조건: 하단 기능 버튼이 작거나 겹쳐서 오터치가 빈번하다.
* 발견된 문제:
  - 첫 플레이에서는 업그레이드 비용, 생산량, 행성 단계 목표가 한 화면에 모두 보이지 않으면 목표 상실이 발생할 수 있다.
  - 네온 파티클이 많을 경우 자원 수치 상승을 가릴 수 있다.
  - AI 기본 안내가 설명문처럼 길면 첫 업그레이드 유도가 약해진다.
* 수정 지시:
  - 첫 행성의 첫 업그레이드는 20~40초 안에 가능하도록 밸런스 담당에게 수치 검토를 요청한다.
  - 첫 AI 메시지는 "에너지 축적 중. 업그레이드로 복원 속도를 올릴 수 있어." 수준의 1~2줄 행동 지시로 제한한다.
  - 파티클은 자원 UI 근처에서 투명도를 낮추고, 숫자 상승 텍스트는 파티클보다 위 레이어에 둔다.
  - 하단 탭 터치 영역은 실제 아이콘보다 크게 잡고 최소 48dp 이상으로 설계한다.
* 성공 기준:
  - 신규 테스터가 설명 없이 첫 업그레이드까지 도달한다.
  - 1~3분 안에 최소 2회 이상의 긍정 피드백을 경험한다.
  - 행성 상태 변화 또는 다음 단계 게이지가 명확히 보인다.
  - 주요 UI 겹침, 닫기 불가 팝업, 의미 불명확 버튼이 없다.
* 검증 방법:
  - 3분 무설명 플레이 테스트를 최소 5회 수행하고 첫 업그레이드 도달 시간, 오터치 횟수, 멈춘 구간을 기록한다.
  - 모바일 세로 화면 3종에서 스크린샷을 비교한다.
  - AI 안내를 끈 상태와 켠 상태의 첫 행동 성공률을 비교한다.
  - QA 1차 반려 조건에 해당하는 항목이 1개라도 있으면 Rejected 처리한다.
* 승인 상태: Approved

## 15. 수정

* 담당 에이전트: Visual Designer, Visual Design Lead, QA Lead
* 목표: QA 1차에서 발견된 첫 플레이 이해도와 조작 피드백 문제를 수정 가능한 작업 단위로 정리한다.
* 구현/기획 범위:
  - 수정 범위는 UI 크기, 색 대비, 안내 문구, 첫 업그레이드 강조, 행성 단계 게이지, 파티클 밀도 조정에 한정한다.
  - 신규 행성, 신규 시스템, 추가 컷신, 복잡한 튜토리얼은 QA 1차 수정 범위에서 제외한다.
* 산출물:
  - QA 1차 수정 지시서: Blocker는 즉시 수정, Major는 QA 2차 전 수정, Minor는 출시 전 우선순위로 분류한다.
