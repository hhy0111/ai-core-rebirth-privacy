# 감정형 AI 행성 복원 게임 - 게임 디자인 및 밸런스 초안

문서 상태: MVP 기획 및 밸런스 초안  
담당 역할: Game Designer, Game Design Lead, Game Balance Agent, Balance Lead  
적용 범위: 20단계 실행 순서 중 1~9단계, 19단계  
중요 전제: 본 문서의 모든 수치는 출시 확정값이 아니라 QA와 플레이 테스트로 검증해야 하는 기준값이다.

## 공통 범위 통제

* Google Play Android 전용 2D 방치형 하이브리드 캐주얼 MVP를 기준으로 한다.
* 개인 개발자가 유지할 수 있도록 서버, 멀티플레이, 랭킹, 길드, PvP, 대형 컷신, 복잡한 실시간 연출 시스템은 제외한다.
* 광고와 인앱 상품은 보상형, 편의성, 시간 단축, 외형 중심으로 설계한다.
* 무료 유저도 모든 행성, 진화, Prestige에 접근 가능해야 한다.
* 밸런스 데이터는 정적 JSON/ScriptableObject/CSV 중 하나로 관리 가능한 구조를 권장한다.

## 1. 요구사항 분석

* 담당 에이전트: Game Designer, Game Design Lead, Game Balance Agent, Balance Lead
* 목표: 감정을 가진 AI 코어가 죽은 행성을 복원하고 은하를 확장하는 2D 방치형 모바일 게임의 MVP 요구사항을 출시 가능 범위로 정리한다.
* 구현/기획 범위:
  * 핵심 루프: 자동 생산, 업그레이드, 행성 상태 변화, 진화 선택, 다음 행성 이동, 반복 성장.
  * MVP 콘텐츠: 행성 5개, 행성 상태 4단계, AI 성향 3종, 자원 3종, 업그레이드 20종, 이벤트 10종, 광고 보상 5종, 인앱 상품 6종, 간단 Prestige.
  * 세션 기준: 1~3분 안에 보상 수령, 업그레이드, 진행 변화 중 최소 1개 이상이 발생해야 한다.
  * 제외 범위: 멀티플레이, 서버 랭킹, 길드, PvP, 대형 서버 시스템, 과도한 스토리 컷신.
* 산출물:

| 구분 | MVP 해석 | 밸런스 기준 |
|---|---|---|
| 핵심 재미 | 행성이 살아나는 시각 변화와 수치 성장 | 3분 내 최소 2회 업그레이드 체감 |
| 차별 요소 | AI 성향과 진화 선택 누적 효과 | 성향별 생산/위험/안정 보너스 차별화 |
| 반복 동기 | 다음 행성 해금과 희귀 자원 획득 | 행성별 고유 자원과 이동 조건 |
| 수익화 | 보상형 광고와 편의성 IAP | 진행 차단 금지, 광고는 선택형 |
| 유지보수 | 로컬 데이터 중심, 정적 테이블 기반 | 서버 의존 없는 밸런스 패치 가능 구조 |

* 발견된 문제:
  * AI 성향, 진화 선택, 이벤트, 행성 확장을 모두 깊게 만들면 개인 개발자 범위를 초과할 수 있다.
  * 초반에 자원 3종을 모두 노출하면 하이브리드 캐주얼 유저에게 복잡하게 느껴질 수 있다.
  * 광고 보상이 너무 강하면 일반 성장 루프가 무력화되고, 너무 약하면 광고 시청 동기가 사라진다.
  * 오프라인 보상과 시간 변경 악용 가능성이 있다.
* 수정 지시:
  * 1행성에서는 에너지 중심으로 시작하고, 특수 자원과 AI 진화 데이터는 순차 해금한다.
  * AI 성향 효과는 MVP에서 3개 축의 명확한 패시브 보너스로 제한한다.
  * 이벤트는 짧은 선택지 2개와 결과 2~3종으로 제한한다.
  * 오프라인 보상은 최대 8시간, 광고 2배는 최대 1회 적용으로 제한한다.
* 성공 기준:
  * MVP 범위가 개인 개발자가 구현 가능한 정적 데이터 중심 구조로 축소되어 있다.
  * 출시 필수 루프와 제외 범위가 명확하다.
  * 무료 유저 진행이 막히지 않는다.
* 검증 방법:
  * 1~3분 플레이 플로우 시뮬레이션.
  * 행성 1개 완주 시간, 광고 시청 빈도, 업그레이드 클릭 빈도 점검.
  * 팀장 리뷰에서 과도한 기능 여부 확인.
* 승인 상태: Approved

## 2. 핵심 루프 정의

* 담당 에이전트: Game Designer, Game Design Lead, Game Balance Agent, Balance Lead
* 목표: 짧은 모바일 세션에서 반복 성장을 체감할 수 있는 핵심 루프를 정의한다.
* 구현/기획 범위:
  * 기본 루프: 자원 자동 생산 -> 업그레이드 구매 -> 행성 복원도 증가 -> 단계 변화 -> 진화 선택 -> 다음 행성 이동.
  * 세션 루프: 접속 -> 오프라인 보상 확인 -> 업그레이드 1~3회 -> 이벤트 또는 터치 가속 -> 종료.
  * 장기 루프: 행성 5개 완료 -> 은하 안정도 누적 -> Prestige -> 일부 성장 요소 유지.
* 산출물:

| 루프 길이 | 플레이어 행동 | 보상 | 설계 의도 |
|---|---|---|---|
| 10초 | 에너지 확인, 터치 가속 | 즉시 생산량 증가 | 첫 반응성 확보 |
| 30초 | 저가 업그레이드 구매 | 초당 생산량 상승 | 성장 체감 |
| 1분 | 행성 복원도 상승 확인 | 단계 진행률 변화 | 목표 인지 |
| 2~3분 | 이벤트 선택 또는 광고 보상 선택 | 자원/버프/리스크 | 짧은 세션 변주 |
| 10~20분 | 행성 단계 완료 | 신규 기능/자원 | 재접속 동기 |
| 1~2일 | 다음 행성 이동 | 신규 비주얼/희귀 자원 | 확장 목표 |
| 5~7일 | 첫 Prestige | 영구 보너스 | 장기 유지 |

핵심 루프 공식 초안:

| 항목 | 공식 초안 | 비고 |
|---|---|---|
| 기본 생산량 | 초당 에너지 = 행성 기본값 x 업그레이드 배율 x AI 성향 배율 x 이벤트 배율 | 오프라인에도 적용 |
| 터치 가속 | 10초 동안 생산량 +100%, 쿨다운 60초 | 광고 없이도 사용 가능 |
| 복원도 증가 | 누적 사용 에너지 / 행성 복원 요구량 | 구매가 진행도에 기여 |
| 단계 전환 | 복원도 25%, 55%, 85%, 100% 기준 | 시각 변화와 기능 해금 연결 |
| 다음 행성 이동 | 현재 행성 완성 + 이동 비용 지불 | 희귀 자원 일부 필요 |

* 발견된 문제:
  * 완전 방치만 강조하면 1~3분 세션에서 조작 재미가 약하다.
  * 반대로 터치 가속이 너무 강하면 방치형 정체성이 약해진다.
  * 행성 단계가 수치만 바뀌면 핵심 컨셉이 전달되지 않는다.
* 수정 지시:
  * 터치 가속은 보조 수단으로 두고 생산 핵심은 자동 생산과 업그레이드에 둔다.
  * 행성 단계 전환마다 배경 색, 지형, 궤도 이펙트, AI 반응을 반드시 바꾼다.
  * 1분 내 최소 1개 업그레이드 구매가 가능하도록 초반 비용을 낮춘다.
* 성공 기준:
  * 첫 3분 안에 업그레이드 3회 이상, 행성 복원도 변화 1회 이상을 경험한다.
  * 1일차 안에 1번 행성 완성이 가능하다.
  * 다음 행성 이동 이유가 신규 자원, 비주얼, AI 반응으로 명확하다.
* 검증 방법:
  * 스프레드시트 또는 간단 시뮬레이터로 0~3분, 30분, 1일 성장 곡선 확인.
  * QA Agent B가 3분 세션 5회 반복 후 피로도와 목표 인지 여부 기록.
* 승인 상태: Approved

## 3. MVP 범위 확정

* 담당 에이전트: Game Designer, Game Design Lead, Game Balance Agent, Balance Lead
* 목표: 첫 출시에서 구현할 콘텐츠 수량과 제외 범위를 확정한다.
* 구현/기획 범위:
  * 행성 5개, 자원 3종, 업그레이드 20종, 이벤트 10종, 광고 보상 5종, 인앱 상품 6종, 간단 Prestige만 포함한다.
  * AI 성향은 생명형, 산업형, 전투형 3개로 제한한다.
  * 진화 선택은 각 행성 1회, 총 5회 발생한다.
* 산출물:

| 카테고리 | MVP 수량 | 출시 초안 범위 | 제외/후순위 |
|---|---:|---|---|
| 행성 | 5 | 고유 이름, 색상, 희귀 자원, 상태 4단계 | 절차적 행성 생성 |
| 행성 상태 | 4 | 붕괴, 활성화, 성장, 완성 | 세부 하위 단계 |
| AI 성향 | 3 | 생명형, 산업형, 전투형 | 복합 성격 트리 |
| 자원 | 3 | 에너지, 희귀 자원, AI 진화 데이터 | 자원 4종 이상 |
| 업그레이드 | 20 | 생산, 저장, 복원, AI, 이동 계열 | 장비/파츠 파밍 |
| 진화 선택 | 3계열 | 각 행성 1회 선택 | 긴 분기 스토리 |
| 랜덤 이벤트 | 10 | 선택지 2개 중심 | 복잡한 연쇄 퀘스트 |
| 광고 보상 | 5 | 생산 가속, 오프라인 2배, 이벤트 강화, 복원 속도, 무료 상자 | 강제 전면 광고 |
| 인앱 상품 | 6 | 광고 제거, 패키지, 스킨, 패스 | 확률형 고가 상품 |
| Prestige | 1구조 | 은하 기억으로 영구 생산 보너스 | 다층 환생 시스템 |

* 발견된 문제:
  * 인앱 상품 6종은 개인 개발자에게 운영 부담이 될 수 있다.
  * 프리미엄 은하 패스는 라이브 운영 요소로 확장될 위험이 있다.
  * 이벤트 10종은 텍스트와 결과 QA 비용이 필요하다.
* 수정 지시:
  * 패스는 시즌제가 아니라 일회성 프리미엄 진행 보상 트랙으로 제한한다.
  * 인앱 상품은 소모성보다 영구 편의와 외형 중심으로 구성한다.
  * 이벤트는 동일한 UI 템플릿과 보상 공식으로 관리한다.
* 성공 기준:
  * 모든 MVP 항목이 로컬 데이터와 단일 클라이언트 구현으로 가능하다.
  * 출시 후 확장할 수 있지만 첫 버전 완성에 필요한 양이 과하지 않다.
* 검증 방법:
  * 각 콘텐츠 항목에 필요한 아트, 코드, QA 수량을 산정한다.
  * PM 기준으로 1인 개발 8~12주 MVP 구현 가능성 검토.
* 승인 상태: Approved

## 4. GDD 작성

* 담당 에이전트: Game Designer, Game Design Lead, Game Balance Agent, Balance Lead
* 목표: 개발자가 바로 구현 기준으로 삼을 수 있는 MVP 게임 디자인 문서 구조를 정의한다.
* 구현/기획 범위:
  * 게임 정체성, 플레이 목표, 화면 구조, 진행 구조, 콘텐츠 목록, 수익화 원칙, 밸런스 기준을 포함한다.
  * 내러티브는 짧은 AI 대사와 행성 설명으로 제한한다.
* 산출물:

### GDD 핵심 정의

| 항목 | 내용 |
|---|---|
| 한 줄 소개 | 감정을 가진 AI 코어가 죽은 행성을 복원하거나 활용하며 은하를 확장하는 2D 방치형 게임 |
| 목표 유저 | 짧은 세션으로 성장 체감을 원하는 하이브리드 캐주얼/방치형 유저 |
| 핵심 화면 | 중앙 행성, 상단 자원, 하단 탭, AI 메시지 패널 |
| 주요 조작 | 업그레이드 선택, 터치 가속, 진화 선택, 이벤트 선택, 행성 이동 |
| 핵심 보상 | 생산량 증가, 행성 비주얼 변화, 신규 자원, AI 성향 변화, Prestige 보너스 |
| 실패 조건 | 진행 불가 실패는 없음. 이벤트 리스크는 일시 디버프만 허용 |

### 기본 화면 구성

| 영역 | 기능 | 밸런스/UX 주의점 |
|---|---|---|
| 상단 자원 UI | 에너지, 희귀 자원, AI 진화 데이터 표시 | 초반에는 잠긴 자원은 흐리게 표시 |
| 중앙 행성 | 상태 변화, 생산 이펙트, 복원도 표시 | 스크린샷만 봐도 단계 차이가 보여야 함 |
| AI 패널 | 조언, 성향 반응, 이벤트 추천 | 대사는 1~2문장 제한 |
| 하단 버튼 | 업그레이드, 이동, AI, 이벤트, 상점 | 5개 이하 유지 |
| 팝업 | 진화 선택, 광고 보상, 오프라인 보상 | 닫기와 보상 흐름 명확화 |

* 발견된 문제:
  * GDD가 과도하게 세계관 중심이 되면 구현 우선순위가 흐려진다.
  * 하단 기능 버튼 5개는 모바일에서 복잡할 수 있다.
* 수정 지시:
  * GDD 본문은 루프, 데이터, UI, 밸런스 순으로 작성한다.
  * 이벤트 버튼은 이벤트가 있을 때만 강조하고, 상시 복잡도를 낮춘다.
  * AI 패널은 별도 메뉴이면서도 메인 화면에 짧은 메시지가 노출되도록 한다.
* 성공 기준:
  * 개발, 아트, QA가 같은 기능 범위를 이해할 수 있다.
  * 첫 빌드에서 필요한 화면과 데이터가 누락되지 않는다.
* 검증 방법:
  * 각 화면을 1문장 사용자 행동으로 설명 가능한지 확인.
  * 기능별 구현 우선순위를 P0/P1/P2로 분류.
* 승인 상태: Approved

## 5. 자원/업그레이드 구조 설계

* 담당 에이전트: Game Designer, Game Design Lead, Game Balance Agent, Balance Lead
* 목표: MVP 자원 3종과 업그레이드 20종의 용도, 해금, 성장 곡선을 설계한다.
* 구현/기획 범위:
  * 자원은 에너지, 희귀 자원, AI 진화 데이터 3종으로 제한한다.
  * 업그레이드는 생산, 저장, 복원, AI, 이동 5계열 x 4종으로 구성한다.
  * 비용 증가는 초반 완만, 중반 명확, 후반 Prestige 유도 형태로 설계한다.
* 산출물:

### 자원 3종 수치 테이블

| 자원 | 해금 시점 | 주요 획득처 | 주요 사용처 | 기본 밸런스 초안 |
|---|---|---|---|---|
| 에너지 | 시작 즉시 | 자동 생산, 터치 가속, 오프라인 보상 | 대부분의 업그레이드, 행성 복원 | 초반 1분 내 3회 구매 가능 |
| 희귀 자원 | 1행성 활성화 후 | 행성 단계 완료, 이벤트, 무료 상자 | 행성 이동, 고급 업그레이드 | 행성별 5~80개 획득 |
| AI 진화 데이터 | 1행성 성장 단계 후 | 진화 선택, 이벤트, Prestige | AI 업그레이드, 성향 보너스 강화 | 행성당 1~3개 획득 |

### 업그레이드 비용 공식 초안

| 계열 | 비용 공식 | 효과 공식 | 의도 |
|---|---|---|---|
| 생산 | baseCost x 1.22^level | 생산량 +8%/레벨 | 가장 자주 누르는 성장 |
| 저장 | baseCost x 1.28^level | 오프라인 보상 한도 +6분/레벨 | 재접속 가치 증가 |
| 복원 | baseCost x 1.30^level | 복원도 획득 +5%/레벨 | 행성 단계 진행 |
| AI | 에너지 + AI 데이터 | 성향 효과 +2~4%/레벨 | 선택 누적 강화 |
| 이동 | 에너지 + 희귀 자원 | 다음 행성 조건 충족 | 장기 목표 |

  * 업그레이드 20종을 모두 동일 UI에 노출하면 정보 과부하가 발생한다.
  * AI 데이터 사용처가 적으면 진화 선택 보상이 약하게 느껴진다.
  * 비용 감소 효과가 중첩되면 밸런스가 무너질 수 있다.
* 수정 지시:
  * 업그레이드는 계열 탭 또는 추천 3개 우선 노출 방식으로 정리한다.
  * AI 데이터는 AI 업그레이드와 Prestige 보너스에 사용해 장기 가치를 만든다.
  * 비용 감소 총합은 MVP에서 최대 20%로 제한한다.
* 성공 기준:
  * 첫 3분 내 U01/U02/U09 중심으로 3회 이상 구매 가능하다.
  * 1행성 완성 전 자원 3종의 용도를 모두 한 번 이상 경험한다.
  * 업그레이드 선택지가 많지만 핵심 추천이 명확하다.
* 검증 방법:
  * 3분, 30분, 1일 플레이 타임 기준 구매 가능 업그레이드 수를 시뮬레이션한다.
  * 무료 유저 기준 광고 없이도 1행성 완성이 가능한지 확인한다.
* 승인 상태: Approved

## 6. AI 시스템 설계

* 담당 에이전트: Game Designer, Game Design Lead, Game Balance Agent, Balance Lead
* 목표: AI 캐릭터가 단순 안내 UI가 아니라 플레이 선택과 성장 방향에 영향을 주는 동료처럼 작동하도록 설계한다.
* 구현/기획 범위:
  * AI 성향은 생명형, 산업형, 전투형 3종으로 제한한다.
  * 성향은 진화 선택 누적으로 결정되며, 가장 많이 선택한 계열이 대표 성향이 된다.
  * MVP에서는 대규모 대사 시스템 대신 상태별 짧은 템플릿 메시지를 사용한다.
* 산출물:

### AI 성향 밸런스 테이블

| 성향 | 말투 방향 | 기본 보너스 | 추천 경향 | 리스크 |
|---|---|---|---|---|
| 생명형 AI | 따뜻하고 안정적 | 오프라인 보상 +15%, 이벤트 디버프 -10% | 안정 성장, 복구, 보호 | 순간 생산 폭발이 약함 |
| 산업형 AI | 효율 중심, 냉정함 | 업그레이드 비용 -8%, 기본 생산 +8% | 생산 최적화, 비용 절감 | 이벤트 안정성이 보통 |
| 전투형 AI | 공격적, 리스크 선호 | 리스크 이벤트 보상 +25%, 터치 가속 +20% | 고위험 고보상 | 디버프 발생 시 손실이 큼 |

### 진화 선택 누적 영향

| 선택 누적 | 결과 | 플레이 영향 |
|---:|---|---|
| 같은 계열 1회 | 임시 성향 표시 | AI 대사와 추천 선택지 변화 |
| 같은 계열 2회 | 대표 성향 확정 | 성향 기본 보너스 100% 적용 |
| 같은 계열 3회 이상 | 심화 성향 | 성향 보너스 +5%, 해당 계열 이벤트 추가 보상 |
| 계열 혼합 | 균형형 상태 | 보너스는 가장 높은 계열 기준, 동률이면 선택 팝업 제공 |

### AI 메시지 트리 초안

| 상황 | 생명형 예시 | 산업형 예시 | 전투형 예시 |
|---|---|---|---|
| 접속 | "행성이 조금 더 숨을 쉬기 시작했어요." | "오프라인 생산 정산이 완료됐습니다." | "쌓인 에너지로 바로 밀어붙이자." |
| 업그레이드 가능 | "복원 드론을 강화하면 안정적이에요." | "현재 최고 효율은 코어 발전기입니다." | "생산보다 가속을 먼저 올리면 빠르다." |
| 이벤트 발생 | "위험을 낮추는 선택을 권장해요." | "기대값이 높은 선택지는 두 번째입니다." | "보상이 큰 쪽으로 가자. 손실은 회복하면 된다." |
| 행성 완성 | "이 별은 다시 살아났어요." | "행성 효율이 최대치에 도달했습니다." | "좋아, 다음 목표로 이동한다." |

* 발견된 문제:
  * AI 추천이 항상 정답처럼 보이면 선택의 의미가 줄어든다.
  * 성향 보너스가 너무 강하면 특정 성향만 정답이 될 수 있다.
  * 대사량이 과도하면 제작 비용이 커진다.
* 수정 지시:
  * AI 추천은 "권장"으로 표현하고 결과를 100% 공개하지 않는다.
  * 성향 보너스는 장단점이 명확하도록 설계하고 총합 기대값은 비슷하게 맞춘다.
  * MVP 대사는 상황 x 성향 기준 최소 세트로 시작하고 반복 빈도를 제한한다.
* 성공 기준:
  * 유저가 AI 성향 차이를 첫 행성 안에서 인지한다.
  * 선택 누적이 다음 행성의 생산, 이벤트, 대사에 영향을 준다.
  * 어느 성향도 명백한 정답이 되지 않는다.
* 검증 방법:
  * 성향별 1일차 성장량 차이가 ±10% 범위 안인지 시뮬레이션한다.
  * QA에서 AI 메시지가 반복적으로 거슬리지 않는지 확인한다.
* 승인 상태: Approved

## 7. 행성/확장 구조 설계

* 담당 에이전트: Game Designer, Game Design Lead, Game Balance Agent, Balance Lead
* 목표: 행성 5개의 상태 변화, 생산 차이, 이동 조건, 확장 동기를 설계한다.
* 구현/기획 범위:
  * 각 행성은 붕괴, 활성화, 성장, 완성 4단계를 가진다.
  * 행성별 기본 생산량, 희귀 자원, 이벤트 성향, 완료 보상이 다르다.
  * 다음 행성 이동은 현재 행성 완성과 이동 비용을 조건으로 한다.
* 산출물:

### 행성 상태 4단계

| 단계 | 복원도 | 비주얼 방향 | 기능 변화 | 보상 |
|---|---:|---|---|---|
| 붕괴 상태 | 0~24% | 갈라진 지표, 어두운 코어, 잔해 | 기본 생산만 가능 | 첫 업그레이드 해금 |
| 활성화 | 25~54% | 코어 점등, 에너지 라인 생성 | 희귀 자원 등장 | 이벤트 낮은 확률 해금 |
| 성장 | 55~84% | 생태/시설 확장, 궤도 이펙트 | AI 진화 데이터 획득 | 진화 선택 발생 |
| 완성 | 85~100% | 밝은 대기, 완성된 링/도시 | 다음 행성 이동 가능 | 완료 보상, 생산 보너스 |

### 행성 5개 수치 테이블

| 번호 | 행성명 | 테마 | 기본 생산량 | 복원 요구 에너지 | 희귀 자원 | 이동 조건 | 예상 완료 시간 |
|---:|---|---|---:|---:|---|---|---|
| 1 | 에코-01 | 폐허 생태 행성 | 1.0/sec | 600 | 생체 결정 | 250 에너지, 희귀 5 | 45~90분 |
| 2 | 루멘 벨트 | 네온 광물 행성 | 3.0/sec | 3200 | 루멘 광석 | 900 에너지, 희귀 15 | 4~8시간 |
| 3 | 세라 코어 | 고대 구조 행성 | 8.5/sec | 14000 | 세라 파편 | 3500 에너지, 희귀 35 | 12~24시간 |
| 4 | 나이트 폴드 | 불안정 암흑 행성 | 22/sec | 62000 | 암흑 입자 | 9000 에너지, 희귀 55 | 1~2일 |
| 5 | 오리진 게이트 | 은하 관문 행성 | 60/sec | 260000 | 원초 핵 | 12000 에너지, 희귀 80 | 2~3일 |

### 행성 완료 보상

| 행성 | 완료 보상 | 다음 플레이 영향 |
|---|---|---|
| 에코-01 | 전체 생산 +5%, AI 데이터 1 | AI 성향 해금 완료 |
| 루멘 벨트 | 희귀 자원 획득 +10% | 이동 업그레이드 가치 증가 |
| 세라 코어 | 이벤트 보상 +10% | 이벤트 선택 동기 증가 |
| 나이트 폴드 | 오프라인 보상 +15분 | 재접속 가치 증가 |
| 오리진 게이트 | Prestige 해금, 은하 기억 1 | 장기 반복 루프 시작 |

* 발견된 문제:
  * 완료 시간이 실제 광고 시청 여부에 따라 크게 달라질 수 있다.
  * 4~5행성에서 요구량이 과하면 MVP 이탈이 발생할 수 있다.
  * 행성별 차이가 숫자만 있으면 확장감이 약하다.
* 수정 지시:
  * 광고 보상 없이도 5~7일 안에 첫 Prestige가 가능하도록 조정한다.
  * 각 행성은 고유 이벤트 1~2개와 고유 희귀 자원 이름을 가진다.
  * 행성 이동 직후 첫 1분은 빠른 업그레이드 1회가 가능하도록 시작 보너스를 둔다.
* 성공 기준:
  * 첫 행성 완료 전 이탈을 줄이기 위해 90분 안에 명확한 완성 목표가 보인다.
  * 행성 이동 시 새 배경, 자원, AI 반응이 즉시 달라진다.
  * 첫 Prestige까지 무료 플레이 기준 5~7일 범위에 들어온다.
* 검증 방법:
  * 광고 미사용, 보상형 광고 보통 사용, 적극 사용 3개 시나리오로 완료 시간을 계산한다.
  * 각 행성 첫 3분 플레이에서 업그레이드 가능 횟수와 목표 인지 여부를 QA한다.
* 승인 상태: Approved

## 8. 이벤트 시스템 설계

* 담당 에이전트: Game Designer, Game Design Lead, Game Balance Agent, Balance Lead
* 목표: 짧은 세션에 선택 변주와 AI 성향 반응을 제공하는 랜덤 이벤트 10종을 설계한다.
* 구현/기획 범위:
  * 이벤트는 2개 선택지, 짧은 결과, 보상 또는 일시 리스크로 구성한다.
  * 진행 불가, 자원 영구 손실, 저장 데이터 손상형 이벤트는 금지한다.
  * AI 성향에 따라 추천 선택지가 달라질 수 있다.
* 산출물:

### 이벤트 발생 규칙

| 항목 | 수치 초안 | 비고 |
|---|---:|---|
| 기본 발생 간격 | 4~8분 | 온라인 플레이 중 |
| 오프라인 중 발생 | 없음 | 정산 복잡도 감소 |
| 동시 보유 | 1개 | UI 복잡도 제한 |
| 만료 시간 | 3분 | 짧은 세션 대응 |
| 부정 효과 최대 시간 | 5분 | 이탈 방지 |
| 광고 강화 | 보상 +100% 또는 디버프 제거 | 선택형 |

* 발견된 문제:
  * 리스크 이벤트가 잦으면 방치형의 편안함을 해친다.
  * 이벤트 보상이 업그레이드보다 강하면 기본 루프가 약해진다.
  * 광고 강화가 항상 최선이면 광고 압박으로 느껴진다.
* 수정 지시:
  * 부정 결과는 시간 제한 디버프만 허용하고 복원도 하락은 MVP에서 제외한다.
  * 이벤트 기대 보상은 일반 생산 1~4분치 범위로 제한한다.
  * 광고 강화는 하루 체감 이득이 크되 필수는 아니도록, 기본 보상도 충분히 제공한다.
* 성공 기준:
  * 이벤트가 1~3분 세션에서 선택 재미를 제공하지만 진행을 방해하지 않는다.
  * AI 성향별 추천 차이가 자연스럽게 보인다.
  * 이벤트 보상 기대값이 일반 성장 루프를 압도하지 않는다.
* 검증 방법:
  * 30분 세션에서 이벤트 발생 횟수, 광고 선택률, 부정 결과 체감 기록.
  * 성향별 추천 선택지 분포가 한쪽으로 치우치지 않는지 확인.
* 승인 상태: Approved

* 담당 에이전트: Game Designer, Game Design Lead, Game Balance Agent, Balance Lead

  * 인앱 상품은 Pay-to-Win 금지, 시간 절약, 외형, 편의성 중심으로 제한한다.

  * 생산 가속 패키지와 광고 보상이 중첩되면 성장 곡선이 크게 벌어진다.
  * 프리미엄 은하 패스는 라이브 서비스처럼 오해될 수 있다.

  * 결제 실패나 광고 실패가 보상 미지급 외의 진행 불가 상태를 만들지 않는다.
* 검증 방법:
  * 무료, 광고 적극 사용, 소액 결제, 광고 제거 구매 4개 성장 시나리오 비교.
  * 보상 지급 실패와 중복 지급 방지 테스트 케이스 작성.
* 승인 상태: Approved

## 19. 밸런스 검수

* 담당 에이전트: Game Balance Agent, Balance Lead, Game Design Lead
* 목표: MVP 수치가 초반 성장 체감, 무료 유저 진행 가능성, 광고/IAP 압박 완화, 반복 플레이 유지력을 만족하는지 검수한다.
* 구현/기획 범위:
  * 자원 생산, 업그레이드 비용, 행성 이동 조건, 오프라인 보상, 광고 보상량, 인앱 상품 가치, Prestige 보상 구조를 검수한다.
  * 본 문서의 수치는 검증 전 초안이며, QA 1~3차 결과에 따라 조정한다.
* 산출물:

### 밸런스 목표 지표

  * 행성 4~5 요구량은 QA 2차 이후 20~30% 조정 여지를 둔다.
  * 오프라인 보상은 마지막 저장 시간, 최대 보상 시간, 비정상 시간 점프 감지값을 함께 저장한다.
* 성공 기준:
  * 초반 3분 안에 성장 체감이 있고, 첫 행성 목표가 명확하다.
  * 광고 보상은 유의미하지만 광고 없이는 진행이 막히지 않는다.
  * 결제 상품은 시간 단축과 외형 중심이며 핵심 콘텐츠를 잠그지 않는다.
  * 첫 Prestige까지 무료 기준 5~7일 목표에 들어온다.
